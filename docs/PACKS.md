# Path packs

A pack is one JSON file holding several places (pins and beacon records with their anchors and
paths). It lets places move between phones: an orientation and mobility specialist can map a
building once and hand the file to a student, a friend can share a campsite, or you can back up
your own places.

* Import: Find a place → **Import a pack** → pick the file (any app that can hand over a `.json`
  file works: Files, Mail, Messages, AirDrop). Existing places with the same id or the same beacon
  are kept; the rest are added, marked "from <pack name>", and are searchable by that name.
* Export: Find a place → **Share my places as a pack** creates `octopi-places.json` with everything
  on the phone and opens the share sheet.
* Sample: [sample-pack.json](sample-pack.json) (also a unit-test fixture, regenerated by the
  `FixtureWriter` test when `OCTOPI_WRITE_FIXTURE` is set).

Format (version 1), see `Octopi/Sources/OctopiCore/Store/PlacePack.swift`:

```json
{
  "format": "octopi-pack",
  "version": 1,
  "name": "Student Center",
  "author": "O&M office",
  "notes": "Ground floor, from the Mass Ave entrance.",
  "createdAt": "2026-11-05T22:13:20Z",
  "places": [ { "...": "Place records exactly as the app stores them" } ]
}
```

Each place carries: `id`, `name`, `kind` (`virtualPin` or `physicalBeacon` with its identifier),
`origin`, optional `anchor` (GPS fix + quality), `path` (waypoints east/north in metres from the
anchor, with `start`/`turn`/`spacing`/`end` kinds), `confidence`, `createdAt`, and optional
`pressureDeltaKPa`, `frameID`, `source`. A place without an anchor can only be navigated from
where its path began, and the app says so.

Future packs may add fields; readers ignore unknown keys. A `version` greater than the app's is
refused with a spoken explanation.
